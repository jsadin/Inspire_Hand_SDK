# 项目提示词（新增产品通用规则）

这份给 **AI 协作者** 用。人看固定步骤和机型表，用 [新增机型清单.md](新增机型清单.md)；分支、提交、yaml 起名，用 [开发与Git约定.md](开发与Git约定.md)；分层和线程，用 [项目架构说明.md](项目架构说明.md)。

下面「可粘贴段」是通用规则：灵巧手、夹爪、新总线都适用。某一款产品的寄存器表、帧示例、自检命令写在该机型自己的 `docs/` 里，不要再往本文件堆。

---

# 【项目提示词】（整段可粘贴）

```
你正在为仓库 Inspire_Hand_SDK（ROS2 Humble + C++17）添加新产品。
新产品包括：新灵巧手、新夹爪、已有机型的新总线（485 / CAN-FD / Serial-CAN）。
灵巧手和夹爪走同一套分层，只是接口包形状不同。

开工前必须先读：
  docs/新增机型清单.md     —— 步骤顺序、必改文件、文末机型矩阵
  docs/开发与Git约定.md   —— 分支、提交、CI、禁止入库、yaml 命名
需要时再读 docs/项目架构说明.md。

不要改 colcon 三层目录，不要改仓库默认 yaml，不要为每个机型新建 launch。
一次提交只做一件事；新机型拆 2～3 个 PR：协议+单测 → 接口+适配器+示例 yaml → 文档。

═══════════════════════════════════════════════════════════════
0. 先判断类别，再抄最近的一套实现（不要从零发明架构）
═══════════════════════════════════════════════════════════════
对照 docs/新增机型清单.md 文末矩阵，按「产品形态 + 总线 + 关节数」选模板：

  6 关节灵巧手 485/CAN-FD     → RH56H1（独立接口包；触觉 version2 压阻）
                                电容触觉 version1 才看 RH56F1
  13 关节灵巧手 485/CAN-FD    → RH5DG2
  24 关节腱绳 485             → RH524J1（帧继承 RH5DG2，只改寄存器与关节数）
  Serial-CAN 灵巧手           → RH56DFX
  夹爪 RS485                  → EG5CD1（protocol.type 必须写 EG5CD1）
  夹爪 Serial-CAN / USB-CAN   → EG2-4C2

能继承已有帧格式就继承，只覆写 REGISTER_MAP、读长度、关节数和机型特例。
字段看起来一样也要独立接口包（历史：RH56H1 不复用 rh56f1_interfaces）。
手册有的能力才做；手册没有的模式不要补（历史：4C2 只有 catchMode 0/1，不做触控组合）。

═══════════════════════════════════════════════════════════════
1. 分层与运行时（不可破坏）
═══════════════════════════════════════════════════════════════
工作区根 = git 根 = colcon 工作区根。src/ 只有一层：

  src/inspire_serial_core/   裸库：Protocol、串口、DeviceWorker、ConfigLoader、
                             工厂自注册（必须 SHARED .so，STATIC 会丢掉 REGISTER_PROTOCOL）
  src/driver/                ROS 包 inspire_control_ros2：节点、RegisterController、
                             各机型 InterfaceAdapter、权威 yaml、launch
  src/interfaces/<Model>/    每机型独立 msg/srv 包

通信三种，所有产品统一：
  话题：约 50Hz 定时读寄存器并发布；订阅命令话题写
  服务：按需 set/get；每个 .srv 响应段必须有 string message，把 IoError 说给调用方
  组合服务（力控/触控等多寄存器连写）：ioWriteSequence 在 DeviceWorker 上原子执行，
     步间隔 constexpr kCompositeStepMs = 3，在工人线程 sleep，禁止在 ROS 回调里抢串口

线程：
  MultiThreadedExecutor；每设备一个 DeviceWorker（队列 + 单工作线程）保证事务不交错；
  每设备一个 Boost.Asio 收包线程；定时器与服务/订阅分 CallbackGroup。
  一机一口一个工人。两台手不要共用同一个 port（同口会互相覆盖）。

═══════════════════════════════════════════════════════════════
2. 必做链路（顺序不要跳）
═══════════════════════════════════════════════════════════════
A. 协议  src/inspire_serial_core/
   ① include/<Model>_…protocol.hpp + src/<Model>_…protocol.cpp，实现 Protocol 九个虚函数：
      getRegisterAddress / buildReadCommand / buildWriteCommand / parseResponse /
      validateChecksum / parseTouchData / writeRegister / readRegister / readTouchData
   ② 文件末尾 REGISTER_PROTOCOL("类型名", 类名)
   ③ .cpp 挂进 CMakeLists.txt 的 add_library(...)
   ④ config_loader.cpp::interfacesProfileFromProtocolType() 增加前缀匹配，返回 "<Model>"
      未知类型要报错，不要 silently 当成别的机型
   ⑤ tests/test_<model>_….cpp：组帧、校验和、解析、错误帧；无触觉则断言 NotSupported
      加入 tests/CMakeLists.txt。不依赖真串口。

B. 接口包  src/interfaces/<Model>/
   package.xml 的 <name> 全小写下划线：rhxxxx_interfaces / egxxxx_interfaces。
   灵巧手：仿同自由度已有包（6→H1/F1，13→DG2，24→J1）。
   夹爪：仿 EG5CD1 / EG2-4C2（GripperState + 标量 srv + 手册有的组合 srv）。
   不要因为「字段差不多」去复用别人的包。

C. 适配器  src/driver/
   ① <Model>_interface_adapter 实现 wireTopics / wireServices /
      publishRegisterData / publishTouchData
   ② interface_adapter_factory.cpp 增加 interfaces_profile == "<Model>" 分支。
      未匹配时工厂仍会落到 RH5DG2InterfaceAdapter —— 新产品必须显式分支，禁止靠这个兜底
   ③ CMakeLists.txt：find_package、可执行文件、ament_target_dependencies
   ④ package.xml 增加 <depend>
   ⑤ 每条服务/订阅用 rosIncomingHandIdTargetsThisNode 校验 hand_id（0 = 兼容旧客户端）
   ⑥ topic.name 必须是本适配器已认识的名字；yaml 里写了适配器不认识的名字等于没接上

D. 配置  只新增，不覆盖默认
   src/driver/config/device_protocol_<model>_example.yaml
   src/driver/config/ros2_controller_<model>_example.yaml
   protocol.type 一般是 <MODEL>_<bus>（如 RH524J1_485、EG2_4C2_serial_can）。
   已冻结例外：EG-5CD1 必须写 EG5CD1，不是 EG5CD1_485。
   一份 yaml 只有一个 protocol.type。
   devices[].name 必须等于 launch 的 --device。
   启动用现有 inspire_control_single_device.launch.py，用参数指向这两份 example。
   仓库默认 device_protocol_config.yaml / ros2_controller_config.yaml 当前是 RH56H1 CAN-FD，
   不要拿它们当新产品配置。
   裸库 src/inspire_serial_core/config/ 只给非 ROS 示例；ROS 以 driver/config 为准。
   不要再发明 device_protocol_config_<model>.yaml 这种旧别名。

E. 文档
   docs/ 里写协议要点（厂商大 PDF/DOC 不强制入库）。
   README：结构图、接口表、该机型一小节（长文链到 docs/）。
   更新新增机型清单.md 文末矩阵。

═══════════════════════════════════════════════════════════════
3. 硬约束（规范 + 历史踩坑变成的规则）
═══════════════════════════════════════════════════════════════
【命名】
- 寄存器用手册驼峰：angleSet / openLenSet / gripperStatusBlock …
- 新寄存器同时进 REGISTER_MAP 与 REGISTER_READ_LENGTH_MAP（只写不读除外）
- 接口包名、适配器类名、yaml 文件名里的 <model> 要能对上

【手册 vs 跑通的 demo】
- 手册和厂商 demo/SDK 冲突时，以现场跑通的 demo 为准，并在 docs 里写明差异
- 不要把「另一个 demo 的地址算法」套到本总线（见第 4 节 Serial-CAN）

【组帧】
- 485 校验和：sum(byte[2..n-2]) & 0xFF
- Serial-CAN 校验和：sum(ExtId..Meta) & 0xFF
- 写帧 Meta/DLC 填「实际有效数据长度」，不要固定填满；填错会回包但不运动
- 状态块超过单帧上限时在协议层拆帧，不要让适配器发半包

【能力裁剪】
- 无触觉硬件：parseTouchData / readTouchData 返回 NotSupported；话题可保留但不发假数据
- 协议未定义的服务：适配器返回 not_supported，不要空实现装成功
- 组合服务步骤顺序按该产品手册，不要抄别的夹爪的 catchMode 序列

【Git / CI】
- 从最新 master 拉 feat/<主题>，不要在 master 上直接开发
- 提交信息：类型: 用中文写为什么
- CI 必须绿：colcon build、colcon test --packages-select inspire_serial_core、
  scripts/check_clang_format.sh、scripts/run_clang_tidy.sh
- 测试数量不要写死，用 grep 确认至少发现 1 个测试
- 增量编译后若找不到新协议符号，删掉 build/inspire_serial_core 再编
- 禁止入库：build/ install/ log/ .ros_log/、厂商大 PDF、密钥、本机串口残留
- 不要对 master push --force

═══════════════════════════════════════════════════════════════
4. 历史适配里反复出现的通则（按形态套用，不要整段照抄旧机型）
═══════════════════════════════════════════════════════════════
【继承帧，只改表】
  RH524J1 复用 RH5DG2 的 EB 90 帧，寄存器改用 065demo 的 100/200 分区，
  禁止套用 DG2 的 1000+ 地址。新产品若「同一厂商同一帧、另一张表」，照此做。
  关节数决定一次读写字节数；限位、关节顺序、需要协议层对调的轴，以该机型 demo 为准。

【同寄存器也要独立包】
  RH56H1 与 RH56F1 帧和字段几乎相同，仍做 rh56h1_interfaces。
  区别落在触觉 version（1 电容 / 2 压阻）和 TouchData 消息类型。
  新产品「几乎一样但传感器不同」时，复制接口包再改差异，不要 if-else 混在一个包里。

【Serial-CAN / USB-CAN 转串口】
  ExtId 用手册位域编码，不要用「把地址转成二进制字符串再拼接」的 demo 写法。
  USB-CAN 模块上的地址往往是 Modbus 地址，不是原生 socketcan 的 +offset 地址。
  读帧 Meta 按该系列跑通的 demo；写帧 Meta 按实际 DLC。
  0xA5 转义与数据区偏移跟已有 Serial-CAN 协议对齐（先看 RH56DFX / EG2-4C2）。
  跨单帧的状态块在协议层拆读。

【夹爪组合服务】
  前缀用 ROS 参数 <model>_composite_service_prefix（默认常为 /gripper），便于多机。
  只注册手册存在的模式。步骤写进 ioWriteSequence，不要在回调里 sleep。

【EG5CD1 冻结点（改它或仿它时不要「纠正」）】
  protocol.type = EG5CD1（不是 EG5CD1_485）。
  触觉块 20 字节；接近觉按 uint32，不要改成更窄的类型导致错位。

【配置】
  换机型 = launch 参数指向 *_example.yaml，不是改默认文件。
  同型号左右手 = 同一对 example 里两个 devices，不同 port 与 Hand_ID。

═══════════════════════════════════════════════════════════════
5. 自检（按新产品自己的包名/话题，不要写死 /gripper）
═══════════════════════════════════════════════════════════════
[ ] colcon build --packages-select <model>_interfaces inspire_serial_core inspire_control_ros2
[ ] colcon test --packages-select inspire_serial_core（新协议用例必须过）
[ ] ./scripts/check_clang_format.sh
[ ] 用 example yaml 启动 inspire_control_single_device.launch.py，ros2 node list 能看到 <device>_node
[ ] ros2 topic list / ros2 service list 能看到本机型接口包的话题和服务
[ ] 无硬件：单测绿即可合入；有硬件再验定时读与组合写不交错
[ ] README 接口表 + 结构图 + 该机型小节；新增机型清单.md 矩阵已加一行
[ ] 没有改仓库默认 yaml，没有新建多余 launch，没有把 PDF/日志提交进去

═══════════════════════════════════════════════════════════════
6. 不要做的事
═══════════════════════════════════════════════════════════════
- 不要改三层目录，不要把协议写进 driver，不要把 ROS 接口写进裸库
- 不要覆盖 device_protocol_config.yaml / ros2_controller_config.yaml 当新产品配置
- 不要靠 makeInterfaceAdapter 的 RH5DG2 兜底「顺便能跑」
- 不要在 ROS 回调里直接读写串口或长 sleep
- 不要为没有的硬件编造触觉/组合模式
- 不要复用错误自由度或错误总线的接口包
- 不要把 src/inspire_serial_core/config/ 的短名 yaml（如 RH5DG2.yaml）当成 ROS 权威配置
```

## 怎么用

把上面【项目提示词】整段贴进 AI 上下文，再加一句具体任务：

- 「按此规则，为新机型 XXX 做全链路适配；总线是 …，自由度是 …，手册/demo 在 …」
- 「按此规则，把厂商 demo `yyy.py` 收进本仓库（先判断抄哪套模板）」
- 「按此规则，给已有机型 XXX 补一条 CAN-FD / Serial-CAN 通道」
- 「按此规则，只加同型号第二只手（不要新协议，只改 example yaml 的 devices）」

AI 应按清单选模板、改工厂、只加 example yaml、补单测。人验收以 [新增机型清单.md](新增机型清单.md) 为准。

## 选模板时看这些文件

路径模式（把 `<Model>` 换成矩阵里的型号）：

| 层 | 典型路径 |
|----|----------|
| 协议 | `src/inspire_serial_core/include/<Model>_…protocol.hpp` 与对应 `.cpp` |
| 单测 | `src/inspire_serial_core/tests/test_<model>_…protocol.cpp` |
| 接口包 | `src/interfaces/<Model>/` |
| 适配器 | `src/driver/include/<Model>_interface_adapter.hpp` 与 `.cpp` |
| 工厂 | `config_loader.cpp::interfacesProfileFromProtocolType`、`interface_adapter_factory.cpp` |
| 示例配置 | `src/driver/config/device_protocol_<model>_example.yaml`、`ros2_controller_<model>_example.yaml` |

已支持机型、`protocol.type`、接口包名以 [新增机型清单.md](新增机型清单.md) 文末矩阵为准，本文件不维护第二份表。
