# 灵巧手控制项目架构说明

开发约定与加机型步骤见 [开发与Git约定.md](开发与Git约定.md)、[新增机型清单.md](新增机型清单.md)。

## 一、项目概述

本项目是一个基于ROS2的灵巧手与夹爪控制系统，支持通过 RS485 / CAN-FD / Serial-CAN 与多台设备通信。系统采用模块化设计，每台设备一个 `DeviceWorker` 串行化串口事务，提供话题（Topic）和服务（Service）两种通信方式。

### 1.1 核心特性

- ✅ **多设备支持**：支持同时控制多个设备（如左手、右手）；一机一口一个工人，同 `port` 两台手当前不支持
- ✅ **多协议支持**：工厂模式（RH56F1 / RH56H1 / RH56DFX / RH5DG2 / RH524J1 / EG5CD1 / EG2-4C2 等）
- ✅ **动态配置**：通过YAML配置文件灵活配置设备和ROS2接口
- ✅ **双通信模式**：支持话题（实时控制）和服务（按需调用）两种方式
- ✅ **异步串口通信**：基于Boost.Asio的异步串口通信，支持超时和错误处理
- ✅ **统一日志系统**：全局日志管理器，支持文件轮转和级别控制
- ✅ **线程安全**：多线程环境下的安全通信

## 五、关键组件说明

### 5.1 硬件接口层

**功能**：与灵巧手硬件进行物理通信

**组件**：
- **485串口**：通过USB转485适配器连接设备
- **串口设备**：`/dev/ttyUSB0`、`/dev/ttyUSB1`等

**特点**：
- 支持多设备并行通信
- 每个设备独立串口和协议实例
- 异步接收，阻塞式发送

---

### 5.2 设备管理层

**功能**：管理串口设备和协议对象

**组件**：
- **SerialPortBase**：串口抽象基类
  - 基于Boost.Asio的异步通信
  - 支持超时读取
  - 线程安全的接收缓冲区
- **DeviceManager**：设备管理器
  - 管理多个串口设备
  - 端口到设备的映射
- **RingBuffer**：环形缓冲区
  - 缓存串口接收数据
  - 支持帧解析和数据提取

---

### 5.3 协议抽象层

**功能**：实现具体的通信协议

**组件**：
- **Protocol**：协议抽象基类
  - 定义统一的协议接口
  - 命令构建和响应解析
- **具体协议实现**：见 [新增机型清单.md](新增机型清单.md) 矩阵（RH56F1/H1/DFX、RH5DG2、RH524J1、EG5CD1、EG2-4C2）
- **ProtocolFactory**：`REGISTER_PROTOCOL` 自注册；`protocol.type` 前缀推导 `interfaces_profile`

**特点**：
- 工厂模式，易于扩展新协议
- 每个设备独立的协议实例
- 支持动态读取长度

---

### 5.4 ROS2接口层

**功能**：提供ROS2话题和服务接口

**组件**：
- **RegisterController**：设备控制节点
  - 一个设备对应一个节点
  - 支持多个话题和服务
  - 定时器循环读取和发布

**通信方式**：
1. **话题模式（Topic）**：
   - 订阅控制命令话题
   - 定时发布状态话题
   - 实时性高，适合连续控制

2. **服务模式（Service）**：
   - 提供与各寄存器对应的专用服务类型（由机型接口包定义）
   - 按需调用，不参与定时循环
   - 适合单次操作和查询

---

### 5.5 配置系统

**功能**：从YAML文件加载配置

**配置文件**：
1. **device_protocol_config.yaml**：
   - 设备配置（端口、波特率、Hand_ID）
   - 协议类型配置
   - 日志配置

2. **ros2_controller_config.yaml**：
   - ROS2节点配置
   - 话题配置（命令话题、状态话题）
   - 服务配置（Set/Get服务）

**组件**：
- **ConfigLoader**：配置加载器
  - 解析YAML文件
  - 创建协议对象
  - 配置日志系统

---

### 5.6 日志系统

**功能**：统一的日志管理

**组件**：
- **LoggerManager**：日志管理器
  - 全局单例模式
  - 基于spdlog
  - 支持控制台和文件输出
  - 支持日志轮转

**特点**：
- 线程安全
- 支持动态调整日志级别
- 文件自动轮转（按大小和数量）

## 六、线程模型

```
主线程 (inspire_control_node)
│
├─ ROS2事件循环线程池 (MultiThreadedExecutor)
│  └─ RegisterController节点
│     ├─ 定时器回调 (timer 回调组, 互斥, 50Hz)
│     │  └─ 合并背压后 worker_->submit(读+发布)   ← 仅入队，不阻塞
│     └─ 服务/订阅回调 (service 回调组, 可重入)
│        └─ ioWriteRegister/ioReadRegister/ioWriteSequence
│           └─ worker_->submit(...).get()          ← 等待 worker，不与定时器互斥
│
├─ 每设备 DeviceWorker 工作线程 (每个设备一个)
│  └─ 单线程按 FIFO 执行所有串口事务 (读/写/组合序列)
│     └─ protocol_->read/writeRegister() → SerialPortBase
│
└─ 串口异步接收线程 (每个设备一个)
   └─ SerialPortBase::io_thread_
      └─ Boost.Asio异步读取 → receive_buffer_
```

**线程安全机制（串口事务串行化重构后）**：
- 每个设备节点持有一个 **`DeviceWorker`**（请求队列 + 单工作线程）。所有读寄存器 / 写寄存器 / 组合写序列都提交到该 worker，由单线程按 FIFO 执行，从结构上保证「写命令 → 读应答 → 解析」整组事务**永不交错**——这是串口并发正确性的根本保证。
- `RegisterController` 把**定时器**与**服务/订阅**分到不同回调组（定时器=`MutuallyExclusive`，服务=`Reentrant`），配合 `MultiThreadedExecutor`，使「定时读」与「服务/话题写」可在不同执行器线程并行进入；落到串口时由 worker 串行化。
- 定时读合并背压（`read_in_flight_`）：上次读任务未完成则跳过本次，避免 worker 队列堆积。
- 事务起始清空串口 RX 残留；`SerialPortBase` 写入互斥、读取条件变量同步；`RingBuffer` 仅在 worker 线程访问。
- 已移除旧的「定时器暂停（`ioPauseTimer`/`pauseTimer`）」与 EG-5CD1 组合服务经验暂停时长机制——串行化由 worker 结构性保证，不再需要靠暂停躲避冲突。


## 八、扩展点

### 8.1 添加新协议

1. 创建新协议类，继承`Protocol`
2. 实现所有纯虚函数
3. 使用`REGISTER_PROTOCOL`宏注册
4. 在配置文件中指定协议类型

### 8.2 添加新寄存器

1. 在协议类的`REGISTER_MAP`中添加寄存器地址
2. 在`REGISTER_READ_LENGTH_MAP`中配置读取长度（如需要）
3. 在ROS2配置文件中添加话题或服务配置

### 8.3 添加新机型或新设备

- **新产品（新协议/接口包）**：按 [新增机型清单.md](新增机型清单.md) 走协议 → 单测 → 接口 → 适配器 → 示例 yaml，不要改仓库默认配置。
- **同型号再加一台手**：在对应 `*_example.yaml`（或默认配置）里增加 `devices` / `device_nodes`，使用不同 `port` 与 `Hand_ID`。

## 九、性能特性

- **控制频率**：50Hz（20ms周期）
- **串口通信**：异步接收，阻塞式发送
- **超时机制**：读取超时25ms
- **多设备支持**：每个设备独立线程和协议实例
- **内存管理**：使用智能指针，自动管理资源

---

## 十、故障处理

- **串口通信错误**：超时重试，日志记录
- **协议解析错误**：跳过无效帧，继续处理
- **服务调用异常**：try-catch保护，确保响应返回
- **定时器与服务冲突**：由每设备 `DeviceWorker` 单线程串行化所有串口事务，从结构上消除冲突（不再需要暂停定时器）
